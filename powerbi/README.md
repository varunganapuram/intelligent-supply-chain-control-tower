# Editable Power BI project

Open `ControlTower.pbip` in a current Power BI Desktop version supporting PBIP/PBIR. No binary `.pbix` is fabricated. The six report pages and model are generated by `python scripts/export_powerbi.py`.

1. Open the project and change the Power Query **DataFolder** parameter to the absolute `reports/` folder with a trailing slash.
2. Refresh the Import semantic model. The source is the verified CSV reporting layer, so no database password is embedded.
3. Optionally import `theme.json` from View > Themes.
4. Run `acceptance_queries.dax`. Compare numeric values to `reports/kpis.json` and inspect date/state/seller filters.
5. Confirm empty cohorts render blank rates, seller metrics use single-seller orders, and scenario day filters show per-day capacity correctly.
6. Verify risk and scenario tables, page visuals, visual interactions and slicers. Save as `.pbix` if desired, then capture native Power BI screenshots.

## Model relationships

Date 1 -> * Orders; Sellers 1 -> * Orders through primary_seller_id; Orders 1 -> * Risk and Decisions; Scenario 1 -> * Decisions. All filters are single-direction. The Orders table retains customer state and primary category for unambiguous order-grain filtering. Review and SLA measures use order facts only.

The model omits item-level dimensions from this graph to avoid accidentally filtering order KPIs through mixed grains. Item/product facts remain available in PostgreSQL for separate item-level analysis.

Power BI scenario slicers filter precomputed results. Live optimization runs in the Streamlit intervention simulator. Global model test metrics are intentionally disconnected and do not recalculate under state/date filters.
